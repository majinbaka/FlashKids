# FlashKids image concepts

Use this skill for every new or edited FlashKids raster image, including image
generation prompts, app assets, icons, and marketing artwork. Do not use it for
Flutter-drawn elements marked **🔧 VẼ BẰNG CODE** in the concepts; implement
those in code only when that implementation is explicitly in scope.

## Source of truth

`design.md` is the normative UI/UX contract and outranks `concepts/`. Before
creating an image, read:

1. `concepts/README.md` to identify the category and its scope.
2. `concepts/images/00-art-direction.md` in full for the shared palette, STYLE,
   NEGATIVE, mandatory constraints, and export rules.
3. The applicable category brief below, in full. Use its supplied prompt as the
   base and replace only its stated placeholders unless the request requires a
   deliberate variation.

| Image purpose | Category brief |
| --- | --- |
| Mascot or expression | `concepts/images/01-mascot.md` |
| Flashcard subject | `concepts/images/02-flashcard-subjects.md` |
| Deck cover | `concepts/images/03-deck-covers.md` |
| Correct / try-again feedback | `concepts/images/04-feedback-overlay.md` |
| Progress, stickers, rewards | `concepts/images/05-progress-and-rewards.md` |
| Empty, loading, error, or offline state | `concepts/images/06-state-placeholders.md` |
| Onboarding, hero, or child avatar | `concepts/images/07-onboarding-and-avatars.md` |
| Parent Zone illustration | `concepts/images/08-parent-zone.md` |
| Background, texture, or card back | `concepts/images/09-backgrounds-and-textures.md` |

| Store-listing artwork | `concepts/images/11-store-listing.md` |

If no category fits, use the shared art direction and state the proposed asset
purpose before generating. Do not invent an image for a component that the
concepts reserve for code.

## Generation contract

- Preserve the approved flat, picture-book vector language; use the defined
  palette and the shared STYLE and NEGATIVE blocks. The mascot is the approved
  purple baby sloth, not an alternate character.
- Keep UI text, numbers, buttons, frames, logos, and watermarks out of generated
  app artwork. User-facing copy belongs in the localized UI layer. Store
  marketing copy is added separately in layout, never generated by the model.
- Keep the subject unmistakable at 48×48 px, centered where the brief requires,
  with generous negative space and no background clutter. Use transparent PNG,
  sRGB, light-only output when the applicable brief calls for an app asset.
- Treat Kid Zone and Parent Zone differently: Kid Zone is warm and playful;
  Parent Zone remains compact, text-led, and utilitarian. Do not put the mascot
  in Parent Zone unless its concept brief explicitly permits it.
- Communicate positive, retry, completion, or locked states with silhouette,
  pose, or symbols as well as color. Never use alarm red, shame, crying,
  scolding, fear, weapons, or other harsh imagery for children.
- For a related set, keep subject scale, line weight, saturation, composition,
  and mascot design consistent. Generate the mascot reference first when a new
  set depends on it.

## Before accepting output

Check the category-specific checklist and verify that the result has no text or
watermark, is legible at the required small size, has a calm usable background,
and follows its specified aspect ratio, transparent-background requirement,
filename, and export dimensions. Inspect the actual image when available;
regenerate or edit it when it misses a required concept constraint.

When a request conflicts with `design.md` or an approved concept decision,
surface the conflict with file references and ask the user to decide before
generating the affected image.
